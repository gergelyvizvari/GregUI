# Component usability review — 29 September 2026

This pass reviewed the existing component contracts, interactive catalog and reported pricing screenshot, focusing on visible selection, feedback, keyboard operation and reversible actions.

| Finding                                                                                                                 | Change                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Pricing selection was communicated only by a faded disabled button; recommendation was more visible than current state. | Current plan now has a persistent checkmarked badge and accent outline. Recommended remains a separate label. Action areas align at the bottom of cards.           |
| Multiple pricing requests could run concurrently on different cards.                                                    | A shared pending lock disables competing actions. The current card remains the app-confirmed selection; rejection shows retry feedback on the requested card.      |
| Table row selection was easy to lose while scanning.                                                                    | Selected rows now have a background treatment and edge marker, in addition to their checked checkbox.                                                              |
| List–detail selection had only a thin edge.                                                                             | The active item now uses the primary surface, contrasting text and a checkmark.                                                                                    |
| Combobox keyboard focus and selected value were visually ambiguous; long result lists could hide the active option.     | Selected values have a checkmark. Home/End move to the boundary options; active options scroll into view.                                                          |
| Action popovers remained open after an action.                                                                          | An enabled action closes the popover and restores trigger focus.                                                                                                   |
| File selection had no explicit clear action.                                                                            | Clear selected files resets both the native input and the consumer selection callback.                                                                             |
| Member role and privacy controls remained editable while old values were saving, and success was quiet.                 | Related controls lock while saving and show a localized success status. Privacy status follows the saved draft rather than claiming a newly edited draft is saved. |

The catalog's existing empty-result messages, required-field validation, destructive confirmation example, modal focus handling and draft-preserving error flows were retained. This is a focused implementation review, not a claim that every possible application workflow has been user-tested. Manual assistive-technology and real-device validation remain tracked in VERIFICATION.md.
